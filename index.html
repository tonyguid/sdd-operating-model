This operating model defines how Qcells software engineering teams build software using AI-augmented, specification-driven development. It answers three questions: what roles do we need, how do specs flow from idea to production, and how do we manage the work day-to-day.

01 Core Principles

📄 Specs Are the Atomic Unit

Every piece of work is a spec — architecture-grade documents with API contracts, data models, and acceptance criteria. Not user stories. Not tickets. Specs are what architects write and what agents implement.

🤖 AI Writes Code, Humans Provide Judgment

Senior developers orchestrate Claude Code agent teams to implement specs at 3–5x throughput. The role shifts from writing code to directing and curating code.

👥 Smaller, Senior-Heavy Teams

Fewer people, higher caliber. One Sr. Developer with Claude Code agent teams matches the output of 3–5 traditional developers. Quality comes from spec precision, not headcount.

📊 Track Outcomes, Not Effort

Progress is measured in delivered specs and verified functionality — not story points or hours. Direct traceability from investment → spec → feature → business value.

03 How It Works

The model covers three dimensions. Each links to a dedicated detail page.

🔄 Spec Lifecycle

Seven phases from idea to production: Spec → Review → Prioritize → Implement → Validate → Ship → Report. The spec is the thread connecting every role and phase.

See full flow in Work Mgmt →

🤖 Agent Team Patterns

Four patterns for structuring Claude Code agents: lead + sub-agent, parallel execution, sequential pipeline, and single agent. Match the pattern to the spec complexity.

See patterns in Sr. Developer →

📋 Work Management

Scrum-to-SDD mapping, Azure DevOps board setup with spec-based columns, 2-week spec cycles, and 6 adapted ceremonies. Estimation uses S/M/L spec complexity, not story points.

See full details in Work Mgmt →

✅ Quality & Review

When to accept, iterate, or intervene manually on agent output. The 70/30 rule: target 70%+ first-pass acceptance. If below, fix the inputs — specs, context, or prompts.
