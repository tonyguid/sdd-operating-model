Key Insight

The role shifts from "writing code" to "directing and curating code." One senior dev with Claude Code can match the output of 3–5 traditional developers. They need strong judgment about what to delegate vs. handle manually.

Agent Team Patterns

How to structure Claude Code agents for different types of work. Match the pattern to the complexity of the spec.

🧑‍✈️ Lead + Sub-Agent

One lead agent coordinates the overall spec. It spawns sub-agents for isolated tasks — frontend component, backend API, database migration, test suite. The lead reviews and integrates sub-agent output.

Best for: Cross-cutting features

⚡ Parallel Execution

Independent spec units run as parallel agents simultaneously. Each agent works on a separate module with clear interface boundaries. Merge results after all agents complete.

Best for: Multiple independent modules

🔗 Sequential Pipeline

Agents execute in sequence when output of one feeds into the next — e.g., data model first, then API layer, then UI. Each agent inherits context from the previous step.

Best for: Dependent layers

🎯 Single Agent

One agent handles the entire spec end-to-end. Use for small, well-scoped changes — a bug fix, a single endpoint, a UI tweak. No coordination overhead.

Best for: Simple, isolated changes

Task Decomposition Rule of Thumb

If a spec touches more than 3 files or crosses architectural boundaries (frontend + backend), use multi-agent. If it's a single concern in a single area, use a single agent. When in doubt, start with one agent and split when you see it struggling with scope.

Spec-to-Prompt Workflow

The process of translating an Architect's spec into effective Claude Code prompts. Each step builds on the previous.

1

Read the Spec

Extract what matters

Identify the scope, acceptance criteria, data models, API contracts, and system flows. Flag any ambiguities — these will cause poor agent output if left unresolved. Send questions back to the Architect before proceeding.

2

Set Context

Ground the agent in the codebase

Use CLAUDE.md to give the agent project conventions, patterns, and structure. Reference specific files the agent will need to read or modify. Point to existing implementations as examples of the expected pattern. Less is more — only include relevant context.

3

Decompose into Prompts

One prompt per agent task

Each prompt should have a single clear objective, explicit constraints (naming conventions, error handling patterns, test expectations), and a definition of done. Include the relevant acceptance criteria from the spec verbatim.

4

Iterate and Refine

Improve first-pass quality over time

Review agent output against the spec. If quality is low, tighten the prompt — add constraints, provide examples, narrow the scope. Track which prompt patterns produce high first-pass acceptance rates and build a team prompt library.

Quality & Review Workflow

Knowing when to accept, iterate, or intervene manually is the core judgment skill for AI-augmented development.

✅ Accept When

Code meets all acceptance criteria from the spec. Follows existing architecture and patterns. Tests pass (unit, integration). No hallucinated dependencies or imports. Naming and style match conventions. PR is merge-ready.

🔄 Iterate When

Output is close but has gaps — missing edge cases, incomplete error handling, slightly wrong patterns. Give the agent targeted feedback: quote the specific issue, reference the correct pattern, and re-run. Most specs take 1–3 iterations.

🛑 Intervene Manually When

Security-sensitive logic (auth, encryption, access control). Complex debugging that requires system-level understanding. Architectural decisions the agent consistently gets wrong. Performance-critical hot paths. Integration with undocumented external systems.

📋 Verify Every Time

Map each acceptance criterion from the spec to delivered code. Run the full test suite — don't trust agent claims that tests pass. Check for unintended side effects in adjacent code. Review generated tests for meaningful assertions, not just coverage.

The 70/30 Rule

Target 70%+ first-pass acceptance rate from agents. If you're below that, the problem is usually upstream — vague specs, insufficient context in CLAUDE.md, or prompts that are too broad. Fix the inputs before blaming the agent.
